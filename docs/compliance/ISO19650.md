# ISO 19650 conformance

How SiteKeep Community covers the information management requirements of ISO 19650-1:2018 and
ISO 19650-2:2018 that a common data environment (CDE) solution must support. Each row names the
clause, the feature that meets it and the tests that prove it. Model and settings:
[CDE states](../features/CDE_STATES.md).

Status: **done** (shipped and tested), **foundation** (data model in place, behaviour not switched on),
**planned**.

| Id | Clause | Requirement | Feature | Tests | Status |
|---|---|---|---|---|---|
| ISO-0 | 19650-1 §12.1; 19650-2 §5.1.7 | A CDE with the states WIP, Shared, Published, Archived; information containers; per-project configuration | Folder states, information containers (`files.container_id`), `project_cde_settings`, `cde_transitions`, template `"cde"` block | `apps/server/test/cde/migration.test.ts`, `apps/server/test/cde/settings.test.ts`, `apps/web/test/app/cde-labels.test.ts`, e2e `administration-settings.spec.ts` (CDE tab) | foundation |
| ISO-1 | 19650-1 §12.2–12.5; 19650-2 §5.6.3, §5.7.2–5.7.4 | Controlled transitions between states (check, review, authorise, accept); archive on supersession; rejected information returned | Transition table enforced on upload, move and review copy; archive on publication; returned / withdrawn flags | — | planned |
| ISO-2 | 19650-1 §12.1 (metadata); 19650-2 §5.1.7 (status and revision codes) | Suitability (status) and revision codes per container version | Codes per version, profiles `iso_uk_na`, `legacy_r`, `custom`, validation in `addVersion` | — | planned |
| ISO-3 | 19650-1 §12.1 (unique ID); 19650-2 §5.1.7 | A unique identifier for each information container, based on an agreed convention | [Unique document codes](../features/DOCUMENT_CODES.md): `document_codes` register from the naming standard, 409 on reuse by another container, renditions and review copies allowed, rename lock after Shared, conflicts list for live data; refusals opt-in per project (`enforce_transitions`, D-8), a warning otherwise | `apps/server/test/cde/document-code.test.ts`, e2e `documents.spec.ts` (duplicate code upload) | done |
| ISO-4 | 19650-1 §12.1; 19650-2 §5.1.7 | Record of who did what and when (audit trail), tamper evident | [Audit log](../features/AUDIT_LOG.md): append-only `audit_log` with a hash chain (migration 0043, database triggers), chain check (API, screen, `npm run audit:verify`), view / move / state-transition events, IP and user agent, project and system log with filters, CSV export, file history | `apps/server/test/audit/audit-log.test.ts`, `apps/server/test/cde/migration.test.ts`, `apps/web/test/documents/audit-labels.test.ts`, e2e `audit-log.spec.ts`, `administration-settings.spec.ts` (Audit Log tab) | done |
| ISO-5 | 19650-1 §12.2; 19650-2 §5.6.2 | Task teams work in WIP, not visible to other teams until shared | Task teams as project roles, WIP owned by a team, team-only visibility | — | planned |

Tests tagged with an ISO clause run with the full and the Community test suites
([tests](../architecture/tests.md)).
