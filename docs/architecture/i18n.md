# Arayüz dilleri (i18n)

Web arayüzü birden çok dilde çalışır. **Varsayılan İngilizce**; kullanıcı üst çubuktaki
dil menüsünden (Product Tour'un solunda, `EN`/`TR`) değiştirir. Seçim tarayıcıda ve
kullanıcının profilinde (`users.prefs.language`) saklanır, başka cihazda da gelir.

Kütüphane: **i18next** + **react-i18next**. Kod: `apps/web/src/i18n/`.

---

## 1. Yeni dil eklemek (kod değişmez)

1. Klasörü oluşturun:
   ```bash
   npm run i18n:new -w @sitekeep/web -- es Español ES es-ES
   ```
   `locales/es/` açılır: `meta.json` (`"status": "beta"`) ve İngilizce dosyaların
   **aynı anahtarlı, boş değerli** kopyaları.
2. Boş değerleri çevirin (anahtarlar aynı kalır; `labels.json` dahil). Boş kalan
   değer İngilizce görünür, dil yarım haliyle de yayına çıkabilir.
3. İlerleme: `npm run i18n:status -w @sitekeep/web` (dil ve ad alanı başına çevrilen / toplam).
4. `npm test -w @sitekeep/web`: anahtar ve `{{yer tutucu}}` denetimi geçmeli.
5. Hepsi çevrilince `status: "complete"`. `beta` dilde eksik anahtar İngilizceye düşer
   ve menüde “beta” yazar; `complete` dilde eksik anahtar test hatasıdır.

Dil menüsü klasörleri kendisi bulur (`languages.ts`, `import.meta.glob`); Vite her
dilin dosyalarını ayrı parçaya koyar, yalnız seçilen dil indirilir. Sağdan sola dil
(`dir: "rtl"`) `<html dir>`'i çevirir; CSS'te `left/right` yerine `inline-start/end`
kullanılan yerler hazırdır, kalanlar o dil gelince elden geçer.

Çeviri iş akışı: İngilizce JSON'lar kaynak metindir. Çevirmen (insan ya da yapay zekâ)
yalnız JSON görür; koda bakması gerekmez.

## 2. Dosya düzeni

```
apps/web/src/i18n/
├─ index.ts            initI18n, setLanguage, currentLanguage, currentIntlLocale
├─ instance.ts         tek i18next örneği
├─ languages.ts        dil listesi (locales/*/meta.json), varsayılan, yedek dil
├─ resources.ts        İngilizce paket (uygulamayla gelir) ve ad alanı listesi
├─ labels.ts           paylaşılan enum etiketleri: useLabel(), label(), labelEntries()
├─ i18next.d.ts        t() anahtarlarının tipleri (İngilizce dosyalardan)
└─ locales/
   ├─ en/  meta.json + <ad alanı>.json      kaynak dil
   └─ tr/  meta.json + <ad alanı>.json      (labels hariç: §5)
```

**Ad alanı = uygulamanın bir bölümü:**

| Ad alanı | Kod |
|---|---|
| `common` | her yerde geçen düğme ve durumlar (Kaydet, Vazgeç, Sil, Yükleniyor…) |
| `shell` | `src/app/` (üst çubuk, menü, sayfa iskeleti, dil menüsü), `src/shared/` |
| `labels` | paylaşılan enum etiketleri (§5) |
| `auth`, `projects`, `documents`, `works`, `reviews`, `forms`, `schedule`, `sim`, `coordination`, `reports`, `ai`, `admin`, `integrations`, `projectSettings`, `onboarding`, `viewers` | aynı adlı `src/features/*` klasörü (`documents` ayrıca `src/pdf/`, `viewers` `src/viewers/`) |

Yeni bölüm: `locales/en/<ad>.json` + `locales/tr/<ad>.json` + `resources.ts`'e bir satır.

## 3. Kod kuralları

```tsx
import { useTranslation } from "react-i18next";

export function CapacityCard() {
  // First namespace = plain keys; other listed namespaces with a prefix ("common:…").
  const { t } = useTranslation(["admin", "common"]);
  return (
    <>
      <h2>{t("capacity.title")}</h2>
      <button>{t("capacity.actions.runTest")}</button>
      <p>{t("capacity.summary", { registered: 164, active: 97 })}</p>
      <button>{t("common:actions.cancel")}</button>
    </>
  );
}
```

- **Metin kodda yazılmaz.** JSX metni, `title`, `aria-label`, `placeholder`, `alt`,
  hata/bildirim cümleleri, seçenek listeleri: hepsi `t()`. Test bunu denetler (§6).
- **Anahtar = anlam, metin değil:** `capacity.actions.runTest`, `"Canlı Test Et"` değil.
  camelCase, ekran → bölüm → ad sırasıyla.
- **Tam cümle, yer tutucuyla.** Parça birleştirme yok (`t("a") + count + t("b")` yanlış;
  diller sözcük sırasını değiştirir):
  ```json
  "summary": "{{registered}} registered, {{active}} active users"
  ```
- **Çoğul:** `count` ile `_one` / `_other` (i18next, `Intl.PluralRules`):
  ```json
  "files_one": "{{count}} file", "files_other": "{{count}} files"
  ```
  Türkçede ikisi aynı olabilir ("{{count}} dosya"); ikisi de yazılır.
- **Biçimli metin** (kalın, bağlantı): `<Trans i18nKey="…" components={{ b: <b />, a: <Link to="…" /> }} />`,
  JSON'da `"<b>{{name}}</b> sizi davet etti"`.
- **Bileşen dışındaki sabitler** (menü, sekme, seçenek dizileri): metni değil
  **anahtarı** tutar (`labelKey: "nav.items.today"`), ekranda `t(item.labelKey)` ile çevrilir.
  Dil değişince yeniden çizilsin diye modül düzeyinde `t()` çağrılmaz.
- **Bileşen dışı işlevler** (yardımcılar, `confirm()` metni): `i18n.t("ns:key")`
  (`import { i18n } from "src/i18n"`), çağrıldığı anda geçerli dilde.
- **Tarih, sayı, boyut:** `formatDate`, `formatDay`, `formatNumber`, `formatPercent`,
  `formatSize`, `formatRelative` (`shared/lib/format`). Kendi `Intl` çağrınız için
  `intlLocale()`. `"tr-TR"` / `"en-GB"` elle yazılmaz.
- **Veri ≠ arayüz:** kullanıcının yazdığı kod, ad, katman ve klasör adlarının büyük/küçük harfi,
  araması ve sıralaması arayüz diline göre değil `dataLocale()` (Türkçe kurallar: "i" → "İ")
  ile yapılır; İngilizce arayüzde yazılan kod da aynı koddur.
- **Çevrilmeyenler:** kullanıcı verisi (proje, dosya, klasör adı, yazılan not), yapay zekâ
  cevapları, ürün ve standart adları (IFC, BCF, ISO 19650, PDF, Revit…), sunucudan gelen
  hata metinleri (sunucu `Accept-Language`'a göre cevaplar; sonraki adım, §8).
- **Başka ad alanından anahtar:** `useTranslation(["admin", "common"])` ile ikisini de bildirin,
  sonra `t("common:actions.save")`. Tek ad alanı bildirilmişse önekli anahtar tip hatası verir.

### 3.1 Anahtar grupları ve büyük harf

Arayüzde **adlar ve etiketler** Title Case yazılır ([TERIMLER.md](../product/TERIMLER.md)
“Büyük harf kuralı”), cümleler cümle gibi kalır. Hangisinin hangisi olduğu anahtarın
grubundan anlaşılır ve Türkçe için test edilir:

| Grup (anahtar yolunda bir parça) | Ne | Büyük harf |
|---|---|---|
| `title`, `heading` (son parça) | sayfa, bölüm, pencere başlığı | Title Case |
| `actions.*` | düğme, menü komutu | Title Case |
| `tabs.*`, `nav.*`, `menu.*` | sekme, menü öğesi | Title Case |
| `columns.*` | tablo sütun başlığı | Title Case |
| `options.*`, `status.*`, `badges.*` | onay kutusu, seçenek, durum, rozet | Title Case |
| `fields.*` | form alanı etiketi | Title Case (parantez içi açıklama cümle gibi) |
| `hint`, `help`, `description`, `empty`, `placeholder`, `confirm`, `errors.*`, `messages.*` | açıklama, boş liste, onay sorusu, hata, bildirim | cümle |

İngilizce de aynı ayrımı izler: etiketler Title Case (“Run Test”, “Upload Document”),
cümleler sentence case.

## 5. Paylaşılan etiketler

Durum, öncelik, yetki düzeyi, iş kategorisi gibi enum adlarının Türkçesi
`@sitekeep/shared`'deki `*_LABELS_TR` tablolarındadır (sunucu da rapor ve e-postada
kullanır). Web onları doğrudan okumaz:

```tsx
const label = useLabel();
label("issueStatus", issue.status);          // "Open" / "Açık"
labelEntries("folderState");                 // [["wip", "Work in Progress"], …] (seçim kutuları)
```

- `ISSUE_STATUS_LABELS_TR` → tablo adı `issueStatus` (son ek atılır, camelCase).
- Türkçe `labels` ad alanı çalışırken bu tablolardan kurulur (`labels.ts`); `tr/labels.json` yoktur.
- Diğer diller `locales/<kod>/labels.json` çevirir; anahtarlar tablolarla aynı (test).
- Yeni bir `*_LABELS_TR` tablosu eklenince `en/labels.json`'a İngilizcesi yazılır; test hatırlatır.

## 7. Sunucu ve profil

- `PATCH /me/prefs { language }`: profilde saklar (BCP 47 deseni). `GET /auth/me` → `language`.
- Oturum açılınca profildeki dil geçerli olur; profilde dil yoksa tarayıcıda seçilen yazılır.
- Her API isteği `Accept-Language: <dil>` gönderir (`shared/api/client.ts`).

## 8. Sunucu metinleri

Sunucunun ürettiği ve kullanıcının gördüğü metinler de çeviri dosyalarındadır:
`apps/server/src/i18n/locales/<dil>/<ad alanı>.json`. Ad alanı = kaynak klasörü
(`src/works` → `works`, `src/param-change` → `paramChange`), genel olanlar `errors`.
Diller web ile aynıdır (test aynı klasörleri ister); `npm run i18n:new` ikisini birlikte açar.

### 8.1 Kod cümle yazmaz, ad verir

```ts
import { msg } from "../i18n/index.js";

throw badRequest(msg("works:errors.closed", { number: work.number }));
throw notFound(msg("works:entities.work"));          // "Work not found." / "İş bulunamadı."
throw forbidden();                                   // errors:forbidden
```

`msg()` bir **Msg** üretir: `{ key, params }`, düz JSON. Msg olabildiğince geç, okuyanın
dilinde metne çevrilir:

| Nerede | Kimin dili | Nasıl |
|---|---|---|
| HTTP hatası | isteği yapanın | hata işleyicisi `HttpError.msg`'yi çevirir |
| Bildirim | okuyanın | `notify({ title: msg(…) })`; `notifications.message` sütununda saklanır, liste okunurken çevrilir |
| Dışa aktarma (Excel, PDF, CSV), rapor | indirenin | `const t = tReq(req); t("reports:columns.status")` |
| E-posta, başkası için üretilen dosya | alıcının profili | `tFor(profileLanguage(user.prefs))` |

İsteğin dili: `Accept-Language` (web uygulaması geçerli arayüz dilini gönderir) → profil
(`prefs.language`) → kurulumun varsayılanı (`CDE_DEFAULT_LANGUAGE`, yoksa İngilizce).

### 8.2 Çevrilmeyenler

- **Veri:** projeye yazılan varsayılan adlar (hazır iş tipleri, roller, klasör şablonları,
  form kütüphanesi), demo verisi (`src/dev`), kullanıcı verisi. Mevcut projeler bozulmasın
  diye veri bir kez yazıldığı dilde kalır.
- **Modele giden metin:** yapay zekâ istemleri, MCP araç çıktıları, terim yönergeleri.
- **Günlük satırları** (`req.log`, `console`), Türkçe girdiyi eşleyen düzenli ifadeler.

Bunlar Türkçe harf taşıyorsa satır sonu `// i18n-ok: <neden>` ya da dosya başında
`// i18n-ok-file: <neden>` ile işaretlenir.

### 8.3 Denetim

`apps/server/scripts/check-i18n.mjs`: `src/` içinde (locales, dev, scripts, db hariç)
Türkçe harfli dizge kalmadı mı. `test/i18n/i18n.test.ts`: diller web ile aynı, anahtar ve
`{{yer tutucu}}` eşleşmesi, `Accept-Language` seçimi, hata ve bildirimin okuyana göre
çevrilmesi. Sunucu testleri Türkçe koşar (`vitest.config.ts`: `CDE_DEFAULT_LANGUAGE=tr`).

## 9. Modüllerin metinleri

Her SiteKeep modülü kendi ekran ve sunucu metinlerini kendi deposunda taşır:

```
sitekeep-<id>/locales/
├─ server/<dil>/<ad alanı>.json   sunucu metinleri (msg("contracts:…"))
└─ web/<dil>/<ad alanı>.json      arayüz metinleri (t("contracts:…"))
```

- **Ad alanı çekirdekle aynı olabilir.** Dosyalar çekirdeğin ad alanlarına **eklenir** (i18next
  `addResourceBundle`, derin birleştirme). Cost kendi `contracts` ad alanını getirir, AI ise
  `admin` ad alanına "Yapay Zekâ ve MCP" sekmesinin anahtarlarını ekler. Anahtarlar modül
  kodunda aynı kalır.
- **Sunucu:** `ServerModule.locales` (klasör yolu, `migrations` gibi). Çekirdek açılışta
  `registerLocaleFolder()` ile okur. Çekirdekte olmayan dil yok sayılır, boş değer İngilizceye düşer.
- **Web:** `sitekeep-modules.ts` eklentisi kurulu paketlerin `locales/web` klasörünü bulur.
  İngilizce uygulamayla gelir, diğer diller seçilince ayrı parça olarak yüklenir
  (`addModuleLocales`, `src/i18n/index.ts`).
- **Tipler:** modül kendi İngilizce dosyalarını `SiteKeep.ServerResources` /
  `SiteKeep.WebResources` arayüzüne ekler (`server/i18n.d.ts`, `web/i18n.d.ts`). Yanlış anahtar
  modülde de derleme hatasıdır.
- **Enum etiketleri** (durum, tür …): modülün kendi tabloları. Türkçesi modülün `*_LABELS_TR`
  sabitleridir, modül yüklenirken `registerTurkishLabels(...)` ile kaydedilir (sunucu ve web
  girişinde). Diğer diller `locales/shared/<dil>/labels.json` dosyasındadır; çekirdek iki tarafta da
  okur. Web'de `useLabel("contractStatus", …)` tip denetimlidir (`SiteKeep.LabelTables`).
- **Yeni dil:** çekirdeğe klasör açılır (§1). Her modül deposuna da aynı dil klasörü eklenir;
  eklenmezse modül ekranları İngilizce görünür.
- **Denetim:** modül deposunda `test/locales.test.ts` (her dilde İngilizcenin anahtarları ve
  `{{yer tutucu}}`ları). Çekirdekte `apps/server/test/i18n/module-locales.test.ts` ve
  `apps/web/test/i18n/module-locales.test.ts` (kurulu modüllerin metinleri iki dilde de görünür).
- **Hangi anahtar kimde:** bir anahtar yalnız bir modülün kodunda geçiyorsa o modüldedir. Çekirdeğin
  ya da birden çok modülün kullandığı anahtarlar çekirdekte kalır (ör. Planning ile Cost'un
  ortak `sim` / `schedule` anahtarları).

## 10. Sonraki adımlar

- **Paylaşılan paket iletileri** (yapıldı): `packages/shared` içindeki doğrulama, uyarı ve
  etiket işlevleri son parametre olarak `lang` alır (yoksa Türkçe, `SHARED_DEFAULT_LANGUAGE`);
  metinler `sharedText(lang, "<alan>.<anahtar>")` ile `packages/shared/src/locales/<dil>/messages.json`'dan,
  enum etiketleri `labelText(lang, tablo, anahtar)` ile gelir. Sunucu `requestLanguage(req)`,
  web `i18n.language` geçirir. Denetim: `packages/shared/test/i18n.test.ts`.
- **Viewer paketi** (`@7dimensions-project/bim-viewer`): araç çubuğu ve özellik paneli
  metinleri pakete `messages` / `locale` seçeneğiyle verilir; CDE kendi çevirisini geçirir.
- **MCP / yapay zekâ:** “Sor” cevapları kullanıcının diliyle istenir (`termsInstructionTr`
  yanına İngilizce yönerge).
