# 4D and 5D Simulation

Combines the schedule (iş programı) with the model. 4D plays the schedule in the model day by day. 5D calculates element cost from unit prices.
Both are part of the Schedule module.

## Where to Open It

- **Model → Schedule:** the top bar has the "4D Simulation" and "Cost (5D)" buttons.
- **Activity drawer:** the number of linked elements and a "Show in Model" button. The viewer opens with the activity's elements selected.
- **Gantt:** the 🧱 icon on a row shows the number of linked elements.
- **Viewer:** the "🗓 Calendar" button opens the 4D / 5D bar.

Address format: `/p/<proje>/viewer?v=<versiyonlar>&takvim=1&program=<iş programı>&aktivite=<faaliyet kodu>`.

## 4D Playback

- Play / pause. Speed: 1 Day/s, 1 Week/s, 1 Month/s.
- Date slider, "Today" and "Data Date" buttons.
- **Actual:** reported progress up to the data date; the current plan after it.
- **Planned:** baseline dates only. Delays are not shown.
- Colours:
  - Not started: faded or hidden ("Hide Not Started").
  - In progress: the activity's colour.
  - Completed: the model's own colour.
  - Delayed: red.
- If an element belongs to more than one activity: red if any of them is delayed; the in-progress colour if any is under way.
- The "Activities" list shows the work under way on that date and its % complete. Clicking selects the elements and zooms to them.
- "Record Video" records the playback from the start and downloads a WebM file.

## Linking Elements to Activities

### Manually

Select elements in the viewer. Link them to an activity with "Link the selected element" in the bar. Manual links are not affected by rules.

### Link Rules

The "Link Rules" dialog works on one model file. A rule runs on the element index on the server; the browser does not load geometry.

Conditions (all must be met):

- **Storey:** "Kat 2", "+1.03 (+6.83) PERON KATI (SSL)".
- **Class:** IfcSlab, IfcColumn … (IfcWall also covers IfcWallStandardCase).
- **Name contains:** "perde" (shear wall). Case and Turkish-letter differences are ignored.
- **Property = value:** e.g. `Pset_Proje.Bolum = Peron`.
- **Property = activity code / WBS:** a single rule links the whole model. Each element goes to the activity whose code equals the element's value.

Flow:

1. "Suggest Rules" or "+ Add Rule".
2. Counts appear per rule (preview). Unmatched property values are listed.
3. "Apply" writes the links (`activity_links`, kind `ifc_element`, `rule_id` set).

Rules:

- Re-applying only renews the links written by rules. Manual links stay.
- Deleting a rule also deletes the links it wrote.
- When a new version of the model is indexed, previously applied rules are applied to the new version automatically.
- The dialog warns if a rule has been applied to an older version.

### Suggest Rules

Does not use AI; the same input always gives the same result.

| In the activity name | Class |
| --- | --- |
| Perde, Duvar, Tuğla, Bims | IfcWall |
| Kolon | IfcColumn |
| Kiriş | IfcBeam |
| Döşeme, Plak | IfcSlab |
| Merdiven | IfcStair, IfcStairFlight |
| Kazı, Hafriyat | IfcEarthworksCut |
| Temel, Radye | IfcFooting; otherwise a foundation slab (IfcSlab, BASESLAB) |
| Kazık, Çatı, Rampa, Korkuluk, Kapı, Pencere, Cephe, Tavan, Boru, Kanal | the corresponding class |

The keywords are matched in Turkish: shear wall / wall / brick / pumice block, column, beam, slab, stair, excavation, foundation / raft, and pile, roof, ramp, railing, door, window, façade, ceiling, pipe, duct.

- Only classes present in the model are suggested. Missing ones are counted as "skipped".
- The storey is found from the activity name. Levels and "(SSL)" in storey names are ignored: "Peron Katı Kolonları" → "PERON KATI".
- If no name matches, the patterns "Kat 2", "2. kat", "zemin" (ground), "bodrum" (basement) are tried. Then the WBS path is tried.
- If the values of a property match at least two activity codes, a single "property = activity code" rule is suggested.

## 5D Cost

### Import a Unit Price List

- Format: XLSX, XLS, ODS, CSV (`;` or `,`).
- The header row is searched for in the first 30 rows.
- Columns: Poz No (item no.), Tanım (description), Birim (unit), Birim Fiyat (unit price). Optional: Kategori (category), Para Birimi (currency), Resmi Poz Kodu (official item code).
- Units: m, m², m³, adet (count), kg, ton. Spellings such as "m2", "mtül", "ad." are recognised.
- Numbers: both "1.234,56" and "1,234.56" are read.
- Rows without an item no. and a price (headings, subtotals) are skipped.
- An existing item no. is updated. If no currency is given, TRY is used.

### Cost Rules

Rule: element selection (same conditions as 4D) → unit price × quantity × factor.

- **Quantity:** Count or a base quantity: NetVolume, GrossVolume, NetArea, GrossArea, NetSideArea, Length, Width, Height, NetWeight …
- **Factor:** e.g. reinforcement at 100 kg/m³: quantity NetVolume, factor 100, unit kg.
- **Property = item no.:** if an element's property equals a unit price's item no. or official item code, that price is used.
- **Activity (optional):** the cost is spread over that activity's duration. If none is selected, the element's 4D link is used. If the element belongs to more than one activity, the amount is split equally.
- A warning is shown if the unit and quantity do not match (e.g. an m² price, a volume quantity, factor 1).

### Calculation

- Total; breakdown by unit price item (poz), category, storey, class and activity.
- Elements without base quantities are in the "Missing Quantity" list. Their amounts count as 0.
- Cash flow (S-curve), weekly:
  - Planned: linear spread over the baseline dates.
  - Actual: earned value up to the data date (% complete).
  - Forecast: the current plan after the data date.
- Cost not linked to an activity is not part of the curve; it is shown separately.

### In the Viewer

- "Cost" colour mode: a per-element cost heat map with a legend. Elements without cost are faded.
- When an element is selected, its cost lines appear in the bar.
- During playback, the bar shows the planned and actual (later, forecast) cost up to that date.

### Suggest Items

**Suggest Items** on the Cost Rules tab suggests unit prices for the model's element groups (class · type · material): first learned mappings, then the project's AI (it only picks from the candidate list), then keywords. Confirmed rows become cost rules and are written to the memory on the **Learned Mappings** tab. Details: [POZ_SUGGEST.md](POZ_SUGGEST.md).

### Reports and MCP

- Datasets: `model_costs` (element × unit price item rows), `cost_cashflow` (weekly cumulative curve).
- Template: "Cost (5D)" — totals by category and storey, the 10 largest items, missing quantities, cash flow.
- In the report builder, the words "maliyet, birim fiyat, poz, metraj, nakit akışı" (cost, unit price, unit price item, quantity take-off, cash flow) select these datasets.
- MCP / Ask tools: `cde_cost_summary` (project, optional versionId), `cde_4d_state` (date → activities under way and counts).

## API

| Endpoint | What it does |
| --- | --- |
| `GET/POST /projects/:pid/schedules/:sid/link-rules` | Link rules |

| `POST …/schedules/:sid/link-rules/preview` | Counts per rule (drafts too) |
| `POST …/schedules/:sid/link-rules/apply` | Write the links |
| `POST …/schedules/:sid/link-rules/suggest` | Suggest rules |
| `GET …/schedules/:sid/4d-state?date=&mode=` | 4D state on a date |
| `GET/POST /projects/:pid/cost-items`, `PATCH/DELETE …/:id` | Unit prices |
| `POST /projects/:pid/cost-items/import/preview`, `…/import` | List import |
| `GET/POST /projects/:pid/cost-rules`, `PATCH/DELETE …/:id`, `POST …/preview` | Cost rules |
| `POST /projects/:pid/cost-rules/suggest`, `…/suggest/accept`, `…/suggest/reject`; `GET/DELETE /projects/:pid/poz-mappings` | Suggest Items and learned mappings ([POZ_SUGGEST.md](POZ_SUGGEST.md)) |

## Permissions and Module

- Read: project members. The model must be in a folder the user can see.
- Rules, unit prices and applying: project administrator (planning permission).
- If the Schedule module is disabled, all 4D / 5D endpoints return 403 `module_disabled`.

## Limits

- Quantities are read only from base quantities in the IFC (BaseQuantities, Qto_*). They are not calculated from geometry.
- Models exported from Revit with "Export base quantities" turned off have no volumes or areas. Count rules still work; the others show "missing quantity".
- Currencies are not converted; a warning is shown when different currencies are present.
- Rules are tied to a file. In a federated project, separate rules are written for each model.
- The spread uses calendar days and is linear; there are no work calendars or resource curves.
- No demolition or temporary work types.
- Video is WebM only; the browser must support MediaRecorder. No PNG sequence.
- At most 5000 elements per link row; large rules are split across several rows.
- Element cost is recalculated on every request; on very large models this can take a few seconds.
